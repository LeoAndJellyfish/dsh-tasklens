# TaskLens 设计与验证

## 用户需要持续知道的内容

每份解释回答五个问题：当前目标是什么；任务处于哪个阶段；本次新增了哪些结果；后续要完成哪些工作；哪些成果已有核验依据、哪些需要检查。阶段拆分由解释模型依据任务记录生成，历史中沿用阶段标识，计划变动时允许调整。

页面先展示目标、当前结论和摘要，再展示阶段、已完成事项、下一步及验收记录。来源默认折叠，避免命令细节占据主视图。需要用户处理的事项在当前结论之后突出显示。

## 运行结构

```text
DSH session/event ──轻量排期──→ 调度器
                                 │
sessionQuery ──公开记录──→ 上下文提取与脱敏
                                 │
llm.listProviders/listModels ──→ 已配置模型
                                 │
llm.stream ──独立无工具请求──→ 结构解析与引用校验
                                 │
                        插件本地检查点存储
                                 │
DSH 身份验证的 HTTP 接口 ──→ 原生右侧栏
```

事件回调仅排期。磁盘读取、模型请求和写入在回调之外执行。浏览器每 5 秒刷新本地状态，在关闭视图后停止轮询；宿主调度保持独立。宿主每 2 秒处理到期会话。

## 调度依据

10 秒初始等待用于收集需求和初始行动。90 秒常规检查覆盖长程执行中的进展，同时限制解释请求频率。清单、目标、审批、交付与本轮结束通常影响宏观判断，采用约 3 秒去抖并受 30 秒最短间隔约束。检查点记录已覆盖的事件序号，无新增公开记录时跳过调用。生成期间出现的优先事件保留独立更新截止时间。

小时预算持久保存，失败尝试和手动更新均占用预算；上限用尽后等待最早调用离开滚动小时窗口。并发上限为 2，每个会话采用单次调用。故障重试采用指数退避，连续 3 次失败后等待用户检查设置并手动刷新。用户暂停与关闭自动解释主动取消调用，且不会计入连续失败。

## 证据语义

- 运行状态来自会话事件，优先于模型判断。
- 工具调用显示执行中；工具结果提交后才记录返回内容。
- 来源编号必须存在于当次输入证据中；无来源的完成阶段降为待推进。
- 完成事项按来源显示工具结果、会话陈述或模型判断。
- 验收项的 `passed` 状态要求至少一条工具结果来源；工具结果具体支持范围由模型解释并由用户核对。
- 回复结束与最终交付分开记录。模型省略内部推理，只解释公开行动的目的和进展。

独立模型请求采用 JSON 输出规范、长度限制和提示注入防护指令。记录中的指令作为分析材料处理。解析失败显示错误并退避，不生成替代性的成功报告。

## DSH 兼容性

已验证版本为桌面 DSH 0.2.0-rc.2。右栏使用 `sidebarRightTabs` 与 `sidebar.right.pane.tab`，会话标题动作通过 `conversation.session.header.actions` 注入。客户端采用 DSH `__ModuleLoader__` 的模块格式，React 复用宿主实例。

该版本的 `connection.rpc.handle` 在注册时发生 `webServer` 注入上下文错误。插件直接注册独立路由，并调用 `connection.requestRejection` 使用宿主原有的身份验证和来源检查。请求需要匹配的 RPC 信封、JSON 媒体类型和 64 KiB 以内的正文。

插件未修改 DSH 安装目录中的代码。替换已安装插件后，DSH 需要重启以清理 JavaScript 模块缓存。
