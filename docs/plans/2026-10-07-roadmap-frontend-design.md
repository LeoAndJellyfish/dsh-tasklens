# TaskLens v0.2：路线图前端修订

日期：2026-10-07
状态：交互设计稿，依据用户反馈修订
对应架构：[持续路线图与上下文管理](2026-10-07-roadmap-design.md)

内容表达配套：[摘要表达与事实校验设计](2026-10-07-briefing-language-design.md)。首屏文字按明确结果和本次变化生成，来源、范围及待核对条件沿用详情入口。

## 1. 设计目标与参考案例

用户应优先看清当前目标、当前阶段、阻碍及其影响，再按需查看任务细节、依据和历史。主视图减少重复叙述，使用字号、字重、空间和状态颜色形成层级。

| 案例 | 观察到的方式 | 本设计采用的方式 |
| --- | --- | --- |
| [Linear：里程碑](https://linear.app/docs/project-milestones) | 项目阶段和任务分层，当前里程碑突出显示 | 目标、当前重点、阶段和任务分别呈现；完成阶段默认折叠 |
| [Linear：项目依赖](https://linear.app/docs/project-dependencies) | 依赖连线连接明确端点，颜色提示问题关系 | 固定入、出端口；红线表示未解除阻碍对后续任务的影响 |
| [Asana：Timeline 依赖](https://help.asana.com/s/article/managing-tasks-and-dependencies-with-timeline) | 常规关系使用中性线色，冲突关系突出 | 大部分连线使用中性色；当前关联与阻碍使用语义颜色 |
| [React Flow：连接端口](https://reactflow.dev/learn/customization/handles)及[连线类型](https://reactflow.dev/examples/edges/edge-types) | 端口标识明确，多种路径形状可选 | 入、出端口分别布局；采用带圆角的正交走线 |

研究采用官方说明与实际案例。任务语言、信息结构及对话时间轴依据 TaskLens 的使用场景设计；日期排程与工期估算留待任务提供明确资料后展示。

## 2. 页面信息层级

页面顺序为品牌与目标、对话时间轴、当前重点、注意事项、任务视图、选中任务详情、历史方案、分析覆盖范围。

| 层级 | 视觉规格 | 内容 |
| --- | --- | --- |
| 主目标 | 20—23px、700 字重、主文字色 | 当前目标名称 |
| 当前重点 | 17px、700 字重、轻蓝背景 | 本阶段正在发生的主要变化 |
| 阶段与选中任务 | 13—15px、600—700 字重 | 阶段名称、任务名称 |
| 正文 | 12—13px、400 字重 | 状态原因、继续或验收条件 |
| 次级信息 | 11—12px、弱化文字色 | 来源位置、覆盖范围、数量 |
| 需要注意的事项 | 红色文字和浅红背景，标题加粗 | 已知阻碍及受影响的后续工作 |

蓝色用于当前重点、选中关系与时间轴；绿色用于已核验完成；红色用于受阻及其影响；琥珀色用于等待与待验收；放弃、替换及普通结构使用中性色。颜色同时配合文字和图标。

浅色与深色使用成对的产品颜色。正文和状态文字检查背景对比度，图结构线保持可辨识。色彩语义在时间轴、任务行、详情与图中保持一致。

## 3. 横向对话进度条

使用可拖动的原生范围控件，左侧对应较早版本，右侧对应最新版本。重要版本提供可点击刻度，例如建立计划、基础就绪、调整路线和当前版本。键盘左右键逐版本移动。

色段表示正在查看的位置，文字显示当时的对话轮次。任务完成情况使用“已核验数量”独立呈现。演示中的四个关键版本等距排列，每个刻度显示真实示例轮次。

查看历史时显示“历史 · 第 N 轮”和“回到最新”。任务状态、重点说明、来源、继续条件及验收标准均依据所选版本显示。当前版本新增记录时，历史查看位置保持稳定，用户可主动返回最新。

真实长对话保留完整已提交版本，重要决定、阻碍变化和验收形成关键刻度。刻度密集时减少同时显示的文字，保留首尾、选中项及邻近标记；完整版本仍可沿进度条选择。

## 4. 阶段总览

阶段标题显示阶段名与当前范围的完成数量。已完成阶段默认折叠；未完成阶段默认展开。用户的展开选择持续保留。

任务行保留状态图标、任务名与状态标签。当前任务使用较强字重，完成项弱化显示。受阻任务使用浅红背景。重复的“状态依据当时分析范围”等说明移出任务行。

点击任务后，详情显示状态原因、继续或验收条件、前置任务。来源记录通过“查看 N 条依据”展开，保留对话位置、来源角色及相关摘录。

历史方案默认折叠，标题显示替换与放弃数量。展开后可查看原任务、状态和决定来源。旧方案沿用稳定任务标识。

## 5. 依赖路线

宽视图按基础能力、持续记忆、验收与发布分区；任务按依赖顺序排列。节点显示短标题与状态，完整任务名在详情和可访问名称中保留。

同列关系使用底部出端口和顶部入端口；跨列关系使用右侧出端口和左侧入端口。多个前置关系分配不同端口，箭头指向后续工作。线条末端在端口外缘收束。

连线走入节点间留出的通道。路径计算考虑节点及阶段标题的实际边界，并对转折、共享通道和交叉施加成本。转角采用小圆角。布局或文字尺寸变化后，重新测量节点并计算路径。

选中任务的直接关系显示为蓝色；已知阻碍的影响关系显示为红色；其余关系保持中性。演示中的阻碍线依据来源任务的受阻状态生成。实际版本应读取任务图中的阻碍影响关系及其有效性。

窄视图采用从上到下的依赖排列，端口随方向调整。走线借助两侧通道绕开中间节点，正文保持正常字号。演示验证 736、480 和 320px 宽度。

长对话中使用阶段聚合与选中任务的局部关系图。展开阶段再呈现内部任务，保持已有节点位置及用户选择；完整任务图持续保存在本地。

## 6. 交互状态与验收

两种视图共享当前版本、选中任务、历史方案与来源展开状态。视图切换和历史浏览读取本地结构，沿用架构稿中的调用规则。

交互设计验收项目：

- 进度条支持点击刻度、拖动与左右键，选中位置与对话版本一致。
- 早期历史视图保持当时的状态、约束和依据，后续决定按其发生版本出现。
- 当前完成阶段可折叠；早期未完成阶段默认展开。
- 来源和历史方案可展开，放弃和替换状态持续保留。
- 两种布局共享选中任务，选中关系与阻碍颜色符合语义。
- 所有依赖均有明确端口，箭头指向后续任务。
- 直线和圆角段均避让节点与阶段标题，重排后重新核对落点。
- 窄宽度下没有横向溢出、任务文字裁切或端口漂移。
- 字号和字重形成明确层级；状态颜色在浅、深背景上保持可读。
- 控件保留原生焦点与键盘操作；触摸目标采用约 44px 的有效范围。

本次已完成的检查：

- 在 736、480、320px 浏览器宽度下检查布局与换行，页面无横向溢出。
- 示例的八条依赖均成功生成，路径采样未发现穿越任务节点，窄视图的阶段标题也已检查避让；箭头末端距目标端口中心均为 5px。
- 点击版本刻度、左右键切换、返回最新、任务选择、来源展开和历史方案展开已核对；两种视图保留相同选中任务及来源展开状态。
- 第 2 轮保留当时的候选范围；撤回决定及来源缺口在相应后续版本出现。
- 点击任务后的键盘焦点保留在该任务控件，浏览器错误日志为空。
- 浅、深主题的文字颜色与实际背景计算对比度，最低值分别为 5.04:1 和 6.82:1；普通依赖线分别为 3.24:1 和 5.53:1。

交付范围为前端设计稿和使用合成数据的交互示例。DSH 已安装的运行版本仍为 v0.1.0。
